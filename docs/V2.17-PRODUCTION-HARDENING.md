# UNIRAE V2.17 — EVM production hardening

## Scope

UNIRAE is EVM-only. Supported networks are Ethereum, BNB Smart Chain, Robinhood Chain and X Layer. Both testnet and mainnet API/indexer configuration entries are available. Only the four EVM networks are included in this release.

## Changes in this build

- Mainnet backend chain entries: Ethereum (1), BNB Smart Chain (56), Robinhood Chain (4663) and X Layer (196), alongside the four testnet entries.
- Frontend supports a pre-deployment runtime configuration override: set `window.UNIRAE_CONFIG.environment` to `mainnet` before the app script executes. It then switches to mainnet chain IDs, RPC endpoints and explorers. The default remains `testnet`.
- Factory addresses and native/USD feeds remain blank by default. The frontend deliberately refuses to launch until configured addresses match the deployed factory's on-chain feed, platform wallet, fee and curve settings.
- Migration coordinator now rejects pre-created token/WETH pairs, validates router/factory/wrapped-native code/configuration, and accepts native-asset refunds only from the configured router. This avoids a migration revert when a V2 router refunds unused ETH/BNB/ETH-equivalent during `addLiquidityETH`.
- Fee vault factory/curve authorization now rejects addresses without deployed code.
- Buyback executor validates its operator/router dependencies, wrapped-native token, token code and router return amounts.

## Required EVM launch deployment order

1. Deploy the LP locker and the network-specific DEX router/factory integration.
2. Deploy the fee vault with the fixed platform recipient and a reviewed buyback threshold.
3. Deploy the buyback executor with the fee vault as its immutable operator and the verified router/burn sink; configure the executor once on the vault.
4. Deploy the factory with the verified native/USD oracle and approved economic parameters.
5. Authorize the factory on the fee vault, then configure the factory's default fee vault and creator/buyback split. The factory now refuses token launches until this is complete, and a nonzero buyback allocation requires an initialized executor.
6. Transfer administrative ownership to the approved multisig/timelock after verifying every setting.
7. For each launched token, deploy a migration coordinator with the verified router, locker, LP beneficiary, lock expiry and slippage cap; register it on the factory before graduation.

## Mainnet backend environment

Set the following per chain only after verifying RPC, Chainlink feed, wrapped-native asset, DEX factory/router, factory deployment, fee vault and deployment start blocks:

- `RPC_ETHEREUM_MAINNET`, `RPC_BNB_MAINNET`, `RPC_ROBINHOOD_MAINNET`, `RPC_XLAYER_MAINNET`
- `FACTORY_*_MAINNET`, `NATIVE_USD_FEED_*_MAINNET`, `WRAPPED_NATIVE_*_MAINNET`
- `UNISWAP_V3_FACTORY_*_MAINNET`, `FEE_VAULT_*_MAINNET`, `FEE_VAULT_START_BLOCK_*_MAINNET`

Never use a testnet feed or router on mainnet. Do not populate production addresses from examples or guesses.

## Migration tax handling

The factory configures the migration coordinator through the bonding curve. The token then marks that coordinator tax-exempt for initial liquidity provisioning. At graduation the coordinator creates the previously absent token/wrapped-native pair and registers it with the token before the router seeds liquidity. This preserves the disclosed tax rules for later AMM buys and sells without charging transfer tax on initial liquidity. The full sequence still requires Foundry tests and chain-specific testnet execution before mainnet use.

## Release gate

Run `scripts/release-gate.sh` with Node.js 22+, npm, Foundry and network access. The gate performs dependency installation, Prisma validation/generation, backend tests/build and Foundry tests. Then run chain-specific testnet deployments, wallet-based end-to-end tests, reorg/replay tests, oracle outage/staleness tests, DEX migration/LP-lock tests, and independent security review before mainnet activation.

## Not certified by this source build

No contract deployment, live oracle verification, production RPC validation, full integration test, independent audit or production launch has been performed in this environment. Mainnet addresses are intentionally unset. The stock-token registry is an authorization primitive, not a complete regulated tokenized-equity issuance, custody, redemption or trading integration.
