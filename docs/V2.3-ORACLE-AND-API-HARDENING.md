# UNIRAE V2.3 — Oracle and API hardening

## Contract change

The bonding curve no longer makes an unavailable, stale, incomplete, or future-dated USD oracle round a prerequisite for ordinary buys and sells. `_syncGraduation()` attempts the strict `marketCapUsdE8()` read and defers graduation if that read fails. The public `marketCapUsdE8()` view remains strict and reverts for invalid oracle data. This avoids a stale oracle freezing exits while ensuring invalid data cannot trigger graduation.

Graduation can therefore be delayed during an oracle outage. Operators must monitor feed health and the graduation state. Factory launch still requires a valid oracle because initial curve parameters are denominated using the USD feed.

New Foundry test cases cover stale and future-dated rounds while buying and selling. These tests are authored but have not been executed in this environment because Foundry/solc are not installed.

## API change

- Portfolio transfer history scans are capped at 100,000 incoming and 100,000 outgoing rows per request.
- The response exposes scan completeness and scanned row counts.
- A position is marked `coverageComplete: false` when either scan reaches the cap, so a partial indexed balance is not presented as complete.
- Token detail holder-address sampling is capped at 20,000 transfers and the response flags when that sample cap is reached.

These are resource-protection and data-quality signals, not a replacement for a dedicated materialized balance table or complete transfer index.
