# UNIRAE V2.31 — Buyback delivery verification

## Change

`UniraeBuybackExecutor` previously trusted the router's returned `amounts` array as proof that purchased tokens reached the burn sink. A router can return plausible numbers without transferring tokens. The executor now reads the token balance of the burn sink before and after the swap and requires the measured increase to meet `minTokensOut`. The event reports measured delivery rather than the router's claim.

Added Foundry coverage for unauthorized execution, successful delivery, and a router that fabricates return values without delivering tokens. The existing end-to-end fee-vault test mock was also updated to transfer actual test tokens so it models delivery rather than merely returning numbers.

## Validation status

The available Python static checks and production configuration preflight pass. Solidity compilation and Foundry execution remain unverified because neither `forge` nor `solc` is installed in this environment. The backend has no lockfile, so `npm ci` cannot run; dependencies and backend tests remain unverified.

## Security boundary

The balance-delta check proves delivery to the configured burn sink according to the token's `balanceOf` implementation. It does not certify the router, token, liquidity, price, wrapped-native configuration, or burn sink. Those remain chain-specific deployment review requirements.
