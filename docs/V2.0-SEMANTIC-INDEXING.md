# V2.0 semantic EVM indexing

This milestone maps the project's own V1.1 contract events into application records. The factory `TokenLaunched` event registers a token with its bonding-curve address. `Bought` and `Sold` events from each registered curve create idempotent `Trade` records and raw `IndexedEvent` records.

The indexer uses confirmation depth, bounded block batches, per-contract cursors, duplicate-safe inserts, and a replay window beginning one block before the stored tip when the cursor block hash changes. Configure RPC URLs, factory addresses, and start blocks per EVM testnet. The deployed factory must be the V1.1-compatible factory in this source package.

`Trade.amountIn` and `amountOut` are raw integer units (wei for native amount, token base units for token amount); the side field defines which unit is which. No human-readable decimal conversion is performed in storage.

Limitations: this is an event indexer, not a DEX router or liquidity migrator. Reorg recovery replays the previous block and the changed tip, deletes affected event/trade rows, and removes factory-discovered token records and their dependent indexed rows when a factory launch is orphaned. It remains a bounded, per-cursor recovery strategy—not a full chain-wide reconciliation service for deep reorganizations or every downstream cache. Configure unique, dedicated factory and curve addresses.
