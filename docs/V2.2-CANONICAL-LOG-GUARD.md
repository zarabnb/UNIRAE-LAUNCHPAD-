# UNIRAE V2.2 — Canonical log guard

## Change

The semantic factory and bonding-curve indexer now validate every returned log against the canonical block header hash before persisting it. Header lookups are deduplicated per block within each batch. Logs with missing block metadata or a mismatched block hash are discarded. This reduces the chance that an RPC provider's stale/orphaned range response becomes indexed application data.

## Limits

This is an additional consistency check, not a complete reorg-proof indexing architecture. It does not provide chain-wide finality, guarantee atomicity across an entire scan batch, or replace confirmation depth. A production indexer should additionally use a durable per-chain finalized head, transactional batch commits, explicit rollback/replay integration tests against a forked chain, and operational monitoring.

## Tests added

- Keeps logs whose block hash matches the canonical header.
- Drops orphaned logs with a mismatched block hash.
- Fetches each distinct block header once per batch.
- Drops logs without block metadata.
