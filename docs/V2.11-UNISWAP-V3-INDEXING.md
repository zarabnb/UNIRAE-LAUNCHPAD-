# UNIRAE V2.11 — Uniswap V3 execution indexing

## Implemented

- The post-graduation indexer now supports both Uniswap V2-compatible `Swap` events and Uniswap V3 signed-delta `Swap` events.
- V3 swap deltas are normalized by token ordering: positive amounts are paid into the pool and negative amounts are received from it. Buys and sells are classified only when the configured token and quote asset move in opposite directions.
- V3 pools live in a separate `DexPool` table, so V2 migration provenance and V3 pool registration are not conflated.
- `register:v3-pool` validates the pool contract code, configured official factory, `token0`, `token1`, fee tier, wrapped-native quote asset, registered/verified UNIRAE token, and starting block before adding it to the allowlist.
- The shared DEX indexer reads both active V2 pair registrations and active V3 pool registrations. It retains block confirmation depth, cursor hash checks, rewind/replay handling, and per-log provenance.
- V3 fee tiers are restricted to the standard 100, 500, 3000 and 10000 tiers.

## Configure and register a pool

Set the network's `WRAPPED_NATIVE_*` and `UNISWAP_V3_FACTORY_*` values in the backend environment, alongside the corresponding RPC. These addresses must be independently verified for the exact network; do not copy mainnet addresses to a testnet.

After applying database migrations and generating Prisma Client, register a pool:

```bash
npm run register:v3-pool -- <chainId> <uniraeToken> <v3Pool> <wrappedNativeQuote> <poolCreationBlock>
```

Then run the regular DEX indexer:

```bash
npm run start:dex-indexer
```

Use the actual pool creation block as `poolCreationBlock` to avoid scanning unrelated historical logs. The registration command is an operator allowlist action, not automatic discovery of arbitrary V3 pools.

## Migration

Run:

```bash
npm run db:generate
npm run db:migrate
```

Migration `0006_dex_v3_pools` creates the V3 pool registry.

## Important limitations

- V3 pools are not automatically discovered from graduation receipts. They must be explicitly registered after validating the official factory and wrapped-native quote.
- This indexer currently supports direct token/wrapped-native pools only. It does not route through multi-hop paths or accept stablecoin/token quotes.
- The `Trade` model is shared across venues. If the same token has simultaneous V2 and V3 markets, chart candles aggregate their executions into one native-denominated series; venue-specific charts are a separate follow-up.
- V3 fee amounts are not separately calculated or allocated into creator/platform accounting by this indexer.
- No live RPC test, database integration test, full TypeScript build, or production deployment is claimed in this milestone.
